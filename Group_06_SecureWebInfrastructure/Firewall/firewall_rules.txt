FIREWALL CONFIGURATION

PURPOSE

UFW (Uncomplicated Firewall) is used in this project to control
incoming network connections and reduce unnecessary network exposure.

NGINX acts as the main entry point to the web infrastructure,
while the two Python backend servers run locally behind NGINX
on ports 3001 and 3002.

Only the ports required for administration and web traffic are
allowed through UFW.

DEFAULT FIREWALL POLICY

Incoming connections are denied by default:

sudo ufw default deny incoming

Outgoing connections are allowed by default:

sudo ufw default allow outgoing

This means that incoming services must be explicitly allowed
before they can receive connections through the firewall.


ALLOWED PORTS

SSH - Port 22:

sudo ufw allow 22/tcp

Port 22 is allowed for SSH administration.


HTTP - Port 80:

sudo ufw allow 80/tcp

Port 80 is allowed for HTTP traffic. NGINX receives HTTP
requests and redirects them to HTTPS.


HTTPS - Port 443:

sudo ufw allow 443/tcp

Port 443 is allowed for secure HTTPS traffic through NGINX.



ENABLE UFW

The firewall can be enabled using:

sudo ufw enable


FIREWALL VERIFICATION


The configured firewall rules can be checked using:

sudo ufw status verbose

The numbered rules can be displayed using:

sudo ufw status numbered

The required allowed ports are:

22/tcp  - SSH
80/tcp  - HTTP
443/tcp - HTTPS

IPv6 versions of these rules may also appear when IPv6
support is enabled.



BACKEND SERVICES

The project uses two Python backend servers:

Backend 1: 127.0.0.1:3001
Backend 2: 127.0.0.1:3002

The backend services are bound to the loopback interface
127.0.0.1.

Ports 3001 and 3002 are NOT added as public UFW allow rules.

NGINX receives client requests and forwards them internally
to the backend servers.



BACKEND PORT VERIFICATION

The backend listening ports can be checked using:

ss -ltnp | grep -E '3001|3002'

When both backend servers are running, the expected listeners are:

127.0.0.1:3001
127.0.0.1:3002

This confirms that the backend applications are listening on
the local loopback interface.



HTTPS VERIFICATION

HTTPS access through NGINX can be tested using:

curl -sk https://localhost

The -k option is used because the project uses a self-signed
TLS certificate in the local demonstration environment.

A successful request returns a response from one of the
backend servers through NGINX.



HTTP TO HTTPS REDIRECTION

HTTP redirection can be tested using:

curl -I http://localhost

The expected response includes:

HTTP/1.1 301 Moved Permanently
Location: https://localhost/

This confirms that HTTP requests are redirected by NGINX
to HTTPS.



FINAL FIREWALL CONFIGURATION

Public/required ports:

22/tcp  - SSH administration
80/tcp  - HTTP
443/tcp - HTTPS

Internal backend services:

127.0.0.1:3001 - Backend Server 1
127.0.0.1:3002 - Backend Server 2

Ports 3001 and 3002 are not included in the public UFW
allow rules.

This configuration keeps NGINX as the main web entry point
while the backend applications remain locally bound behind
the reverse proxy.
