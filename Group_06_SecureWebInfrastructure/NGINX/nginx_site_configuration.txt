NGINX SITE CONFIGURATION

Purpose:
This configuration uses NGINX as a reverse proxy and load balancer.
Requests are distributed between two backend servers running locally
on ports 3001 and 3002. HTTP traffic is redirected to HTTPS.

============================================================
NGINX CONFIGURATION
============================================================

upstream backend_pool {
    server 127.0.0.1:3001;
    server 127.0.0.1:3002;
}

server {
    listen 80;
    server_name localhost;

    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name localhost;

    ssl_certificate /etc/ssl/certs/the_rooters.crt;
    ssl_certificate_key /etc/ssl/private/the_rooters.key;

    location / {
        proxy_pass http://backend_pool;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

============================================================
CONFIGURATION DETAILS
============================================================

1. Load Balancing
The upstream block defines two backend servers:
- Backend 1: 127.0.0.1:3001
- Backend 2: 127.0.0.1:3002

NGINX distributes incoming requests between these backend servers.

2. HTTP
NGINX listens on port 80 for HTTP traffic.

3. HTTP to HTTPS Redirection
HTTP requests are redirected to the HTTPS version of the requested URL
using a permanent 301 redirect.

4. HTTPS
NGINX listens on port 443 with SSL/TLS enabled.

5. TLS Certificate
The configuration uses:
Certificate: /etc/ssl/certs/the_rooters.crt
Private Key: /etc/ssl/private/the_rooters.key

IMPORTANT:
The private key itself is NOT stored in this GitHub repository.

6. Reverse Proxy
NGINX forwards requests to the backend_pool using proxy_pass.

7. Backend Exposure
The backend applications listen on the loopback interface
127.0.0.1 rather than being directly exposed as public services.

============================================================
VALIDATION
============================================================

The NGINX configuration can be validated using:

sudo nginx -t

The service status can be checked using:

sudo systemctl status nginx

Load balancing can be verified using:

for i in {1..8}; do curl -sk https://localhost; echo; done

The expected result is responses from both Backend 1 and Backend 2.
